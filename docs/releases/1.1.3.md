# UltraSync v1.1.3

Older ComNav panels can report all 128 zone slots even when only a few are
configured. This release excludes slots marked unused by the panel, bringing
the integration's zone list into line with the ComNav web page.

## Zone filtering

- Ignore the `!` unused-zone marker on ComNav web pages version 0.106 and
  earlier. The filter works with HTTP, standard HTTPS and legacy SSL 3.0.
- Keep configured zones, including unnamed zones and zones that are currently
  Ready or closed. A zone does not need to be triggered to be included.
- Preserve original zone numbers and entity IDs, so configured zones retain
  their identities and existing automation references.
- Leave Home Assistant's entity registry intact. Previously created entities
  for unused slots may remain unavailable after upgrading; remove them
  manually only after confirming that they represent unused zones.

## Legacy HTTPS support included

This is the first formal GitHub release of this fork. It also includes the
legacy ComNav connection features introduced in versions 1.1.1 and 1.1.2:

- Optional SSL 3.0 support for panels whose HTTPS service cannot connect with
  modern Python/OpenSSL.
- SHA-256 certificate pinning before sending panel credentials, with requests
  restricted to the configured host and port.
- Automatic certificate discovery during setup and in integration options.
  Enable **Use legacy SSL 3.0**, leave the fingerprint blank, and confirm the
  certificate presented by your panel before it is saved. A separate
  fingerprint-generation command is not required.
- Connection timeouts and protection against overlapping legacy polls.

SSL 3.0 remains obsolete and is intended only for a legacy panel on a trusted
local network. The option handles a responding panel that requires HTTPS; it
cannot recover a module whose network services have stopped responding. See
the [legacy ComNav setup guide](https://github.com/flybrys/ha-ultrasync/blob/v1.1.3/docs/legacy-ssl3.md)
for configuration and limitations.

## Upgrade

1. Download **v1.1.3** for this fork in HACS.
2. Restart Home Assistant.
3. Check the zone list. If old unused-zone entities remain unavailable,
   confirm they are unused before removing them from Home Assistant's entity
   list.

Keep your existing UltraSync integration entry, settings and configured zone
entities. No new SSL configuration is needed if the integration is already
working. This fork requires Home Assistant 2024.12 or newer.

If switching from the original repository, install
[flybrys/ha-ultrasync](https://github.com/flybrys/ha-ultrasync) as a HACS custom
repository with type **Integration**. Only one repository should manage
`custom_components/ultrasync`; keep the Home Assistant integration entry when
replacing the HACS download.

## Validation

- All 63 automated tests pass, including real library parsing of unused slots,
  unnamed zones, noncontiguous zone numbers, status updates and reconnection.
- A read-only check against a legacy ComNav returned its configured zones
  instead of all 128 slots. No alarm settings or Home Assistant configuration
  were changed during that check.
- Home Assistant flow and coordinator tests use scoped stubs; they are not a
  full Home Assistant runtime test.
