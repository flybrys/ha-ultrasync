# v1.1.4 — Configurable panel port

Some legacy ComNav panels serve HTTPS on port 65535 while the usual HTTPS
port 443 is unavailable. Setup and integration options now include a **Port**
field, so an existing installation can select the working port without
recreating its integration or entities.

- Default port: **65535**, unless a port is already saved or included in Host.
- Valid ports: **1–65535**. The separate Port field overrides a port in Host.
- Certificate discovery, login and polling use the same selected port.
- Port selection works with HTTP, standard HTTPS and legacy SSL 3.0.
- Existing entries keep their connection settings until options are saved.

## Upgrade

1. Update this fork to **v1.1.4** through HACS and restart Home Assistant.
2. Open **Settings → Devices & services → UltraSync → Configure**.
3. Set **Port** to **65535** and keep **Use legacy SSL 3.0** enabled for a panel
   using that service. Keep the existing trusted certificate fingerprint.
4. Submit the form. The integration reloads using the new port.

Use your panel's actual port if different. HTTP usually uses 80 and standard
HTTPS usually uses 443. No panel configuration or firmware is changed.

## Validation

All 71 offline tests pass. Regression tests cover port selection and precedence, valid port
ranges, existing entries, certificate discovery, and options saved without a
second login. Config-flow tests use Home Assistant stubs rather than a running
Home Assistant installation. Read-only hardware checks verified the existing
SSL3 client can authenticate and poll a ComNav on port 65535.
An additional anonymous hardware check using the new separate Port setting
returned the login page successfully without sending credentials.
